# Deploy AlgoQuest on Raspberry Pi

## Dependency model

AlgoQuest is a **Bridge client**. Bridge must already be installed and healthy
before AlgoQuest is installed.

```text
Internet
  -> Cloudflare Tunnel (Bridge)
  -> Bridge edge 127.0.0.1:18080
  -> registered hostname
  -> AlgoQuest origin 127.0.0.1:18081
       -> application-local Nginx gateway
            -> Web
            -> Core API -> PostgreSQL
                        -> Judge -> Redis -> worker -> runner containers
```

Bridge knows nothing about AlgoQuest until AlgoQuest calls `bridge register`.
AlgoQuest owns its hostname, origin port, registration manifest, application
containers, data, and systemd unit. Bridge owns public ingress, DNS-to-tunnel
routing, and the shared Host router.

## Prerequisite: install Bridge first

```bash
git clone https://github.com/intqwq/Bridge.git
cd Bridge
sudo bash install.sh
sudo systemctl status bridge-edge --no-pager
sudo systemctl status bridge-cloudflared --no-pager
```

A healthy fresh Bridge has zero application registrations. AlgoQuest's installer
refuses to continue if the Bridge CLI or services are unavailable.

## Install AlgoQuest

```bash
git clone https://github.com/intqwq/AlgoQuest.git
cd AlgoQuest
sudo bash install.sh
```

The AlgoQuest installer does not install Docker, cloudflared, public Nginx, or
DNS infrastructure. Bridge provides the host infrastructure prerequisite.

The installer:

1. verifies Bridge, Docker, Compose, and `jq`;
2. creates `.env.pi` and internal PostgreSQL/Judge secrets;
3. configures Resend, Turnstile, and the owner account;
4. enforces loopback-only host bindings;
5. builds and smoke-tests the application/Judge stack;
6. installs `algoquest.service`, which requires `bridge-edge.service`;
7. verifies `127.0.0.1:18081/healthz`; and
8. registers the public hostname with Bridge using
   `deploy/pi/register-bridge.sh`.

The registration generated by AlgoQuest is equivalent to:

```json
{
  "version": 1,
  "service": "algoquest",
  "routes": [{
    "hostname": "game.intqwq.com",
    "origin": "http://127.0.0.1:18081",
    "health_path": "/healthz",
    "client_max_body_size": "8m",
    "proxy_read_timeout_seconds": 60
  }]
}
```

The public hostname and private origin port can be changed without modifying
Bridge:

```bash
sudo env \
  ALGOQUEST_DOMAIN=game.intqwq.com \
  ALGOQUEST_WEB_PORT=18081 \
  bash install.sh
```

`PUBLIC_HOSTNAME` is persisted in `.env.pi` and consumed by the registration
helper.

## Network boundary

Production Pi host ports remain private:

```dotenv
PUBLIC_HOSTNAME=game.intqwq.com
WEB_BIND_ADDRESS=127.0.0.1
WEB_PORT=18081
API_BIND_ADDRESS=127.0.0.1
API_PORT=8787
JUDGE_BIND_ADDRESS=127.0.0.1
JUDGE_PORT=8788
DB_BIND_ADDRESS=127.0.0.1
DB_PORT=5432
```

`deploy/pi/check-network-boundary.sh` rejects non-loopback host bindings during
manual deployment and at every systemd start. Bridge reaches only the
application gateway on `127.0.0.1:18081`.

The AlgoQuest Nginx under `deploy/nginx/` remains application-local because it
combines the Web UI and `/api` into one origin. It does not own TLS, tunnels,
DNS, or cross-application routing.

## Operations

```bash
./deploy/pi/status.sh
sudo systemctl status algoquest --no-pager
sudo bridge list
curl -fsS http://127.0.0.1:18081/healthz
```

To re-register after changing the public hostname or origin port:

```bash
sudo bash deploy/pi/register-bridge.sh
```

## Install order on a shared Raspberry Pi

```text
1. Bridge      -> neutral edge + tunnel + registrar
2. AlgoQuest   -> private origin, then registers itself
3. any other application -> private origin, then registers itself
```

No Bridge restart or source edit is needed when another application is added.

## Backup

```bash
docker compose --env-file .env.pi exec -T db \
  pg_dump -U algoquest algoquest > algoquest.sql
```

PostgreSQL is durable state; Judge work/cache volumes are disposable.

## Uninstall

```bash
sudo bash uninstall.sh --plan
sudo bash uninstall.sh
```

Before stopping its containers, the uninstaller runs
`bridge unregister algoquest`. This removes only AlgoQuest's Bridge route. The
Bridge platform and every other registered application remain running. The
Cloudflare DNS record may remain pointed at the tunnel; with no registration,
Bridge answers that hostname with its default 404 until the record is removed or
reused.
